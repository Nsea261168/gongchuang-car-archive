# 智能救援小车最终骨架计划

> 状态：已确认的系统设计。本文用于后续逐阶段实现，不代表当前已完成全部功能。

## 1. 总体约定

- H7 是唯一的任务决策与底盘控制中心。
- 泰山派只输出视觉结果；松甲板只执行运动；激光雷达和 IMU 只提供感知数据。
- 旧 `chassis_uart3` 泰山派任务协议必须完全保留，不改帧头、不改解析逻辑。
- 新视觉链路独立使用 UART1；松甲使用 UART7；保留现有 UART5 LD06 驱动与协议；IMU 使用 SPI。
- 所有串口/SPI 中断只搬运数据到缓冲区并记录时间戳。协议解析、定位、避障和任务状态机均在周期任务中运行。
- 任何感知模块都不得直接写电机指令。

## 2. 泰山派到 H7 的视觉协议

### 2.1 链路

- 方向：泰山派 TX -> H7 UART1 RX，必须共地。
- 串口：115200 baud，8N1。
- 发送频率：建议 20 Hz，最低 10 Hz。
- 单向发送：不使用 ACK、不等待 H7 回复。
- 泰山派即使没有识别到任何物料，也必须持续发送空帧。空帧既表示“当前未看到目标”，也作为视觉心跳。

### 2.2 视觉端职责

泰山派每一帧执行以下工作：

1. 检测画面内全部候选物料。
2. 识别物料类别、颜色、置信度和相对画面下边中点的像素坐标。
3. 按 `x² + y²` 从小到大排序，选择最近的最多 5 个目标。
4. 检查预先标定的夹爪限位区（ROI），给出该区域内物料的类别、颜色和背景颜色。
5. 将结果一次性打包成一张完整视觉快照发送给 H7。

泰山派不选择比赛目标、不判断任务优先级、不直接控制底盘、不承担避障。

### 2.3 坐标与标定

- 原点：画面下边中点。
- `x_px`：向右为正，向左为负。
- `y_px`：向画面上方为正；数值通常越小，目标越靠近车体。
- 单位：像素。
- 相机分辨率、夹爪 ROI 矩形、蓝色背景阈值和“连续确认帧数”均保留为实车标定参数，协议不写死具体数值。
- 背景蓝色应连续确认多帧后才上报为有效，建议初始值为连续 3 帧。

### 2.4 固定帧格式（65 字节）

每个串口包均为固定 65 字节，不使用长度字段和变长解析：

```text
A5 5B | VER | TYPE | SEQ | capture_ms | target[5] | jaw_status | CRC16_L CRC16_H
```

| 字段 | 长度 | 说明 |
| --- | ---: | --- |
| 帧头 | 2B | 固定 `0xA5 0x5B` |
| `VER` | 1B | 固定 `0x01` |
| `TYPE` | 1B | 固定 `0x10`，视觉目标快照 |
| `SEQ` | 1B | 每帧加一，0-255 循环 |
| `capture_ms` | 4B | 泰山派取图时刻，`uint32`，小端 |
| `target[5]` | 50B | 5 个固定目标槽位，每槽 10B |
| `jaw_status` | 4B | 夹爪限位区状态 |
| `CRC16` | 2B | CRC-16/CCITT-FALSE，小端 |

> 帧长计算：2 + 1 + 1 + 1 + 4 + 5×10 + 4 + 2 = **65B**。此前 63B 的说法是算术错误，以本文 65B 为准。

### 2.5 目标槽位 `target[i]`（10 字节，小端）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `track_id` | `uint16` | 同一物料跨帧保持一致；未做稳定追踪时填 0 |
| `category` | `uint8` | 物料类别；0 表示本槽位无效 |
| `color` | `uint8` | 物料自身颜色 |
| `x_px` | `int16` | 相对画面下边中点的水平像素坐标 |
| `y_px` | `uint16` | 相对画面下边的竖直像素坐标 |
| `confidence` | `uint8` | 识别置信度，0-100 |
| `flags` | `uint8` | bit0：在夹爪区；bit1：稳定追踪 |

目标数不足 5 个时，剩余槽位的 `category` 填 0。H7 忽略无效槽位。

### 2.6 夹爪区状态 `jaw_status`（4 字节）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `jaw_flags` | `uint8` | bit0：区内有物料；bit1：背景蓝色已连续确认；bit2：夹爪区结果有效 |
| `jaw_category` | `uint8` | 夹爪区物料类别；无物料填 0 |
| `jaw_object_color` | `uint8` | 夹爪区物料颜色；无物料填 0 |
| `jaw_bg_color` | `uint8` | 夹爪区背景颜色；未知填 0 |

### 2.7 枚举与校验

| 字段 | 取值 |
| --- | --- |
| `category` | 0 未知/无效，1 普通物料，2 核心物资，3 伤员，4 危险品 |
| `color` | 0 未知，1 红，2 绿，3 蓝，4 黄，5 黑，6 白 |

- CRC：CRC-16/CCITT-FALSE，多项式 `0x1021`，初值 `0xFFFF`，不反射，异或输出 `0x0000`。
- CRC 覆盖范围：从 `VER` 到 `jaw_status`，不包含帧头 `A5 5B`，也不包含 CRC 本身。
- H7 收到 CRC 错误帧时直接丢弃；只保留最新一张 CRC 正确的视觉快照。
- 连续超过 200 ms 未收到有效视觉帧，H7 判定视觉失效并停止追逐视觉目标。

## 3. H7 调度与任务行为

### 3.1 周期任务

| 模块 | 周期/频率 | 职责 |
| --- | --- | --- |
| IMU 姿态 | 100 Hz | 更新航向等姿态信息 |
| 底盘速度与安全控制 | 50 Hz | 汇总指令、限速、失效停车、下发 UART7 |
| 雷达解析/定位/避障 | 10-20 Hz | 消费现有 LD06 点云，产生定位与避障结果 |
| 视觉消费与目标跟踪 | 20 Hz | 消费 UART1 最新视觉快照 |
| 任务状态机 | 20 Hz | 选择目标并产生期望运动 |
| LCD | 4-10 Hz | 低频显示状态，避免影响控制周期 |

### 3.2 数据新鲜度与安全门控

- 视觉过期：不再追逐视觉目标，状态机回到安全搜索或停车状态。
- 松甲反馈过期：底盘指令归零。
- 雷达过期：进入降速或停车安全策略。
- 底盘只接收最终汇总的 `vx / vy / wz` 指令。
- 任务状态机生成期望运动；雷达安全层可限速或覆盖为停车；最终指令才下发给 UART7。

### 3.3 任务状态机

```text
SEARCH -> APPROACH -> PUSH -> VERIFY -> SEARCH
```

- `SEARCH`：从最新视觉帧选择符合当前任务优先级的目标；没有合规目标时底盘低速原地搜索。
- `APPROACH`：使用 `x_px` 对准、使用 `y_px` 接近；雷达始终提供墙体和敌方车避障。
- `PUSH`：目标进入夹爪区后低速稳定推送。
- `VERIFY`：夹爪区内目标类别/颜色符合预期，且背景蓝色连续确认后，才记为物料进入安全区。
- 已锁定目标连续 0.3-0.5 秒消失、被敌方车遮挡或无法安全接近时，放弃本次目标，加入短时冷却名单后重新搜索。

### 3.4 优先级

- 开局必须先完成一次普通物料，并确认其进入安全区。
- 首次普通物料完成前，其他任务不进入执行状态。
- 解锁后，由 H7 本地任务计数和可配置优先级，在核心物资、普通物料、伤员之间选择下一目标。
- 危险品只作为识别与规避对象，永不作为接近或推送目标。

## 4. 定位与主动避障

- 不重写已能建立点云图的 LD06 驱动。
- 在现有雷达输出上逐步增加：
  1. 已知 3 m × 3 m 围墙的线/角匹配定位；
  2. IMU 航向融合；
  3. 与静态地图不一致的点簇作为敌方车动态障碍；
  4. 局部避障对底盘最终速度的安全门控。
- 视觉用于物料语义识别和近距离推送确认，不承担全局定位。

## 5. 实施顺序与验收

1. 继续独立验证四路松甲闭环调速、方向、急停和反馈超时停车，不与视觉或雷达耦合。
2. 实现 UART1 视觉接收、65B 定长解帧、CRC、时间戳和最新帧缓存；同步更正视觉组协议文档的 63B 表述。
3. 接入统一调度骨架与状态机，先用模拟视觉帧验证搜索、锁定、目标丢失、蓝色完成确认。
4. 接入实车雷达定位与主动避障，逐步提高速度；未经验证不得让视觉结果直接驱动车轮。

验收条件：

- 连续 10 分钟通讯中，UART1 能稳定解析空帧和 1-5 目标帧；乱序或 CRC 错帧不得污染最新有效结果。
- H7 能正确筛选当前优先级目标；目标被对方搬走或遮挡后能安全放弃并恢复搜索。
- 夹爪区目标正确但背景未蓝时不得判定完成；背景蓝色连续确认后才允许完成。
- 雷达、视觉、IMU 任一数据源短时丢失时，底盘不失控；松甲反馈失效必须安全停车。
