# 智能救援视觉识别与推物算法详细方案

## 1. 文档目的

本文用于确定智能救援赛项中“摄像头识别目标、H7 选择目标、车辆接近目标、车头推板推动目标、确认目标进入己方安全区”的完整技术路线。

本文不是 AI 提示词，也不是单纯的代码修改清单，而是后续视觉接入、底盘控制和实车联调共同遵循的系统设计依据。

比赛资料来源为 `intelligence20260617.pdf` 智能救援部分第 34-46 页。正式比赛规则以组委会最终发布版本为准；本文件中明确标注为“待确认”的尺寸、协议和参数，不得在没有实测的情况下视为已验证事实。

## 2. 比赛场景和规则解释

### 2.1 场地模型

初赛场地约为 `3000 mm × 3000 mm` 的正方形区域。场地四周有一定厚度和高度的防护围栏，但资料明确说明防护围栏不是定位基准，因此全局定位仍以 LD06 观测到的场地边界为主。

场地包含：

- S1、S2、S3、S4 四个出发区；
- 两个队伍各自的安全区；
- 物资放置区和伤员放置区；
- 随机摆放的救援目标；
- 出发区前的三根长方形减速带；
- 同时运行的对方救援机器人。

安全区的颜色由现场抽签决定。程序必须在比赛开始前记录己方颜色和出发位置，不能把“蓝色”永久写成己方安全区。

### 2.2 目标分类

当前初赛目标按以下语义处理：

| 颜色/形状 | 目标类别 | 规则和动作 |
|---|---|---|
| 绿色立方体 | 普通物资 | 8 个，5 分；至少完成一个后才能处理高等级目标 |
| 黑色四面体 | 核心物资 | 4 个，10 分；普通物资完成后才解锁 |
| 橙色长方体 | 伤员目标 | 4 个，15 分；一次只能单独转运一个 |
| 浅蓝色立方体 | 危险目标 | 4 个；不是救援目标，不能推动或送入安全区 |

资料说明目标实际颜色可能存在色差，决赛时颜色、形状和摆放方式可能改变。因此正式系统必须以“目标类别、颜色、形状、置信度”的组合语义为依据，不能只用一个 RGB 阈值决定动作。

### 2.3 必须遵守的比赛限制

- 不能使用机械臂抓取救援目标；
- 不能把目标放在机器人上运输；
- 当前机械方案按车头固定推板设计，目标只能通过接触和推动转运；
- 普通物资和核心物资一次最多转运 3 个，首版采用单目标转运策略；
- 伤员必须单独转运；
- 至少将一个普通物资送入己方物资放置区后，才能转运核心物资和伤员；
- 将目标送入对方安全区会计入对方成绩，并产生处罚；
- 进入对方安全区会扣分；
- 危险目标被移出场地或送入安全区会导致本轮结束；
- 目标被推出比赛场地会按类别和数量扣分，并被放回场地中部；
- 两台车接触超过 10 秒后必须被强制分离，计时不会暂停；
- 任何情况下不能主动攻击对方车辆；
- 比赛时间结束、目标全部处理完成或本轮结束后，机器人必须安全退出场地；
- 机器人开始运行后，队员不能再次接触机器人，也不能通过笔记本电脑遥控。

这些限制直接决定任务状态机不能只追求“看到目标就向前走”，而必须同时维护目标合法性、己方区域、对方区域、危险目标和车辆安全边界。

## 3. 系统职责边界

系统采用 H7 单一决策中心：

```text
摄像头 -> UART1 -> 视觉协议解析 -> 视觉快照
LD06   -> UART5 -> 点云/定位/动态障碍快照
BMI088 -> SPI   -> 姿态快照
松甲板 -> UART7 <-> 编码器反馈和最终电机命令

视觉快照 + 雷达定位 + IMU + 松甲反馈
                -> 救援任务状态机
                -> 期望底盘速度
                -> 安全仲裁
                -> UART7
```

各设备职责固定如下：

- 摄像头只识别目标和提供目标相对位置，不选择比赛目标，不避障，不直接控制电机；
- UART1 BSP 只搬运字节和记录通信状态，不解释颜色和目标类别；
- 视觉协议层只负责帧同步、校验和快照发布；
- Task4 继续负责 LD06 全局定位、雷达点云和动态障碍；
- 目标服务负责目标跟踪、筛选、坐标换算和目标评分；
- Task5 负责 `SEARCH -> APPROACH -> PUSH -> VERIFY` 救援流程；
- AppScheduler 是唯一允许周期性发送最终底盘速度的模块；
- LCD 只显示状态和诊断信息，不参与决策。

视觉不能替代 Task4 的全局定位。视觉坐标是车体局部坐标，Task4 输出的是车辆在 3 m × 3 m 地图中的全局 `x/y/yaw`。

## 4. 视觉通信接入前置审计

当前工程的视觉链路还不能直接使用，必须先解决以下问题：

1. `Core/Src/main.c` 当前没有调用 `MX_USART1_UART_Init()`；
2. `Core/Src/stm32h7xx_it.c` 当前没有完整的 `USART1_IRQHandler()` 业务入口；
3. `BSP/UART/bsp_uart1.c` 的实际内容是 UART7 实现，文件名和职责不一致；
4. 工程中没有职责清晰的 `bsp_uart7.c`；
5. `hdma_adc1` 和 `hdma_usart1_rx` 当前都使用 `DMA1_Stream0`，调用 USART1 初始化会破坏 ADC DMA；
6. `CtrBoard-H7_FDCAN.ioc` 没有保存完整可靠的 USART1 配置，后续重新生成代码存在覆盖风险；
7. 队友视觉模块已经完成训练，但实际串口帧格式尚未冻结。

因此视觉算法接入必须先完成通信协议和硬件资源确认。协议未确认前只能使用仿真帧或回放数据，不能让视觉结果驱动车辆。

## 5. 视觉数据契约

队友可以使用任意原始帧格式，但 H7 内部必须统一成同一种快照结构。这样以后即使更换摄像头或修改协议，任务状态机和推板控制也不需要重写。

### 5.1 统一视觉快照

内部快照至少包含：

```text
sequence
capture_timestamp_ms
received_timestamp_ms
valid
target_count
target[5]
jaw_status
crc_error_count
overflow_count
```

每个目标至少包含：

```text
track_id
category
color
confidence
footpoint_x_px
footpoint_y_px
bbox_width_px
bbox_height_px
flags
```

`footpoint_x_px` 和 `footpoint_y_px` 必须表示目标与地面的接触点。目标框中心会随着目标高度和视角变化，不能直接用于推板接近距离。

### 5.2 协议适配原则

项目原有文档提出过 65 字节定长视觉协议。它可以作为候选协议，但必须与队友当前输出逐字段核对。若实际协议不同，只允许替换 `App/Comm` 中的适配层，统一快照、目标跟踪和任务状态机接口不能跟着改变。

协议解析必须支持：

- 帧头搜索和错位恢复；
- 固定长度或明确长度字段；
- 版本和消息类型检查；
- CRC 校验；
- 序号和采集时间戳；
- 无效目标槽位；
- 丢帧和乱序统计；
- UART 缓冲溢出统计；
- 只发布最新一帧 CRC 正确的快照。

空帧表示“当前没有目标”，仍然是有效心跳。超过 `200 ms` 没有有效帧才进入 `VISION_STALE`。

### 5.3 颜色和语义映射

原始协议中的颜色数字不能直接进入任务逻辑。适配层统一映射为：

```text
VISION_GREEN
VISION_BLACK
VISION_ORANGE
VISION_LIGHT_BLUE_DANGER
VISION_UNKNOWN
```

浅蓝危险目标必须与蓝色安全区独立建模。安全区颜色由比赛配置提供，不能由“检测到蓝色”自动推断。

## 6. 摄像头标定与车体坐标

车辆坐标统一为：

```text
车体前方：+Y
车体右方：+X
```

摄像头像素坐标不能直接送入电机控制。必须建立从像素到地面车体坐标的映射。

### 6.1 标定内容

需要实测并保存：

- 相机离地高度；
- 相机相对车体中心的前后偏移；
- 相机相对车体中心的左右偏移；
- 相机俯仰角和水平安装角；
- 图像下边中点的像素坐标；
- 推板中心相对车体中心的偏移；
- 推板有效宽度和接触距离；
- 相机近距离盲区。

### 6.2 像素到地面映射

推荐使用地面单应矩阵；如果镜头畸变和安装变化较大，则使用多个距离标定点建立分段查表。

标定流程为：

1. 在地面放置多个已知距离和左右偏移的标记点；
2. 记录每个标记点的图像接触点；
3. 求出像素到车体平面的映射；
4. 用未参与拟合的点检查误差；
5. 将结果转换为 `x_target_body/y_target_body`；
6. 验证目标越近时 `y_target_body` 单调减小；
7. 验证目标位于车体右侧时 `x_target_body` 为正。

### 6.3 推板接触几何

推板控制不能以车体中心为目标，而应以推板中心为目标：

```text
e_x = x_target_body - pusher_center_offset
e_y = y_target_body - contact_distance
```

目标必须进入推板有效宽度形成的走廊，才能从 `ALIGN` 进入 `CONTACT`。如果目标距离、左右偏差或识别置信度不满足条件，车辆停车等待，不能用高速撞击方式补偿误差。

## 7. 目标跟踪和目标选择

目标跟踪采用“最新快照 + 时间确认 + 空间关联”的方式：

1. 丢弃低于置信度门限的目标；
2. 要求目标连续多帧出现；
3. 优先使用队友提供的 `track_id`；
4. 没有稳定 ID 时使用位置、类别和颜色的最近邻关联；
5. 对位置使用中值滤波或低通滤波；
6. 目标短时丢失时暂时保持锁定；
7. 超过 `300-500 ms` 未恢复时释放目标并停车或重新搜索；
8. 接近失败的目标加入短时冷却名单。

目标优先级不是固定按距离排序，而是受到比赛规则约束：

```text
危险目标：永远禁止
普通物资未完成：只允许绿色普通物资
普通物资完成后：解锁黑色、橙色和剩余绿色
橙色伤员：始终单独转运
```

多个合规目标之间使用以下综合指标：

```text
目标价值 = 比赛分值 × 识别置信度 × 路线安全系数 / 预计完成时间
```

距离短但靠近对方车辆、危险目标或对方安全区的目标，不应优先于距离稍远但路线稳定的目标。

## 8. 全局搜索算法

物料位置随机，车辆不能一直停在起点等待摄像头看到目标。搜索要依赖 Task4 的全局定位结果，在地图内执行覆盖路线。

### 8.1 搜索区域

搜索地图应包含：

- 3000 mm 正方形边界；
- 机器人外形膨胀后的安全边界；
- 己方和对方安全区禁行区域；
- 墙体和围栏安全距离；
- 三根减速带区域；
- 对方车辆动态禁行区；
- 危险目标动态禁行区。

### 8.2 搜索路径

首版使用平行车道或分区覆盖路线：

1. 根据 S1-S4 选择初始方向；
2. 沿一条车道低速前进；
3. 在车道端点停车或低速转向扫描；
4. 进入下一条车道；
5. 视觉发现合规目标后立即暂停搜索；
6. 目标失效时返回最近搜索点；
7. 当前区域覆盖完成后切换下一区域。

全局路径可使用 `50 mm` 分辨率的栅格 A*。A* 只在目标变化、动态障碍变化或原路径失效时重新计算，不能每个 20 ms 控制周期都重新搜索。

起点前三根减速带必须使用独立的低速和加速度限制，避免车体震动造成视觉抖动、雷达丢帧或编码器打滑。

## 9. 接近、对齐和推送算法

### 9.1 APPROACH 粗接近

进入粗接近必须同时满足：

- 目标类别合法；
- 目标连续确认；
- 视觉帧新鲜；
- Task4 全局定位可用；
- LD06 数据新鲜；
- 松甲极性已确认且反馈新鲜；
- 雷达没有近距离对方车辆或危险障碍；
- 目标到己方安全区的规划路径合法。

粗接近阶段速度较低，使用目标相对横向误差修正车头方向。视觉帧过期时不得继续沿旧目标方向前进。

### 9.2 ALIGN 精对齐

差速控制使用：

```text
e_x   = 目标横向位置 - 推板中心偏移
e_y   = 目标前向位置 - 接触距离
e_yaw = 车头方向误差

w = Kx * e_x + Kyaw * e_yaw
v = Ky * e_y

left_speed  = v - w * wheelbase / 2
right_speed = v + w * wheelbase / 2
```

控制量必须经过速度限幅、角速度限幅和加速度限幅。实际增益、死区、接触距离和推板宽度都必须通过实车标定。

只有当目标横向误差进入推板走廊、目标距离进入接触窗口、类别和颜色连续确认时，才允许进入 `CONTACT`。

### 9.3 CONTACT 接触

接触阶段使用极低速度向目标靠近。进入推板或夹爪 ROI 后，视觉模块必须提供接触确认；目标突然消失但没有接触确认时，不能直接认为已经接触成功。

接触异常时：

- 立即停止；
- 保存当前目标和位姿；
- 后退或小角度重新对齐；
- 重新确认目标类别和位置；
- 超过重试次数后放弃目标并加入冷却名单。

### 9.4 PUSH_TO_ZONE 推送

推送阶段使用全局地图规划到己方对应区域：

- 普通和核心物资送往己方物资放置区；
- 伤员送往己方伤员放置区；
- 不允许进入对方安全区；
- 不允许经过危险目标安全缓冲区；
- 推送过程中尽量保持直线；
- 必须转弯时先停车，确认目标仍位于推板前方，再重新对齐；
- 雷达检测到对方车辆、墙体或动态障碍时由安全层停车；
- 推送速度低于普通搜索速度。

首版只推送单个目标。多目标推送只有在实车确认多个目标能够稳定保持在推板有效宽度内，并且路线、放置区和危险目标规则均满足时才允许启用。伤员永远不能与其他目标合并推送。

### 9.5 PLACE_VERIFY 放置确认

到达己方安全区后不能仅根据车辆坐标判定完成，必须执行以下确认：

1. 车辆进入己方安全区外侧的预停位置；
2. 低速将目标推入正确的物资区或伤员区；
3. 停车，避免目标被撞出安全区；
4. 视觉确认目标类别、颜色和目标位置；
5. 确认目标没有压在围栏、隔板或错误区域；
6. 必要时后退一小段，让摄像头重新看到目标；
7. 连续多帧确认成功后才增加任务计数；
8. 确认失败则重新对齐或放弃，不能直接记为完成。

安全区颜色使用比赛开始前配置的己方颜色。不能把已有视觉设计中的“背景蓝色”直接作为所有比赛场景的完成条件。

## 10. 对方车辆和危险目标

LD06 继续承担动态障碍检测。与静态墙体模型不一致、点簇集中且跨帧独立运动的对象标记为对方车辆候选。

安全策略如下：

- 对方车辆进入停止距离，最终速度立即归零；
- 对方车辆横穿推送路线，停止当前推送并等待或重规划；
- 接触时间接近 10 秒时，执行朝空旷方向的后退或转向；
- 分离动作不能主动朝对方车辆加速；
- 浅蓝危险目标进入车头前方或规划路径时，停止并重新规划；
- 危险目标永远不加入目标选择列表；
- 视觉类别不确定时按危险目标处理；
- 雷达安全结果优先于视觉任务状态。

## 11. 调度、通信和安全仲裁

主循环仍采用协作式调度，不引入第二个主循环，不在任务中使用阻塞等待。

推荐周期：

| 模块 | 目标频率 | 说明 |
|---|---:|---|
| BMI088 | 100 Hz | 姿态和短时航向约束 |
| UART7 编码器解析 | 每圈增量处理 | 只保留最新反馈 |
| 底盘安全和速度下发 | 50 Hz | 唯一最终电机输出入口 |
| LD06 定位和障碍 | 10-20 Hz | 更新全局位姿和动态障碍 |
| UART1 视觉解析 | 20 Hz | 处理最新有效帧 |
| 目标服务和 Task5 | 20 Hz | 选择目标和推进状态机 |
| LCD | 5 Hz | 只刷新变化区域 |

安全优先级固定为：

```text
P0：急停、碰撞、危险目标、越界
P1：底盘安全、反馈检查、UART7 下发
P2：雷达定位、动态障碍、视觉协议解析
P3：目标选择和救援任务状态机
P4：LCD 和调试日志
```

以下任一条件出现时，最终速度必须归零或进入限速：

- 编码器极性 ACK 未确认；
- 松甲反馈过期；
- LD06 数据过期；
- 全局定位丢失或质量不足；
- BMI088 异常；
- APPROACH/PUSH 阶段视觉过期；
- 目标跟踪丢失；
- 对方车辆过近；
- 危险目标过近；
- 即将进入对方安全区；
- 任务退出或急停。

## 12. 推荐源码落点

视觉和救援功能不应堆入 Task4。建议按以下职责拆分：

```text

    视觉伺服、差速速度计算、推板接触控制

    SEARCH、APPROACH、PUSH、VERIFY 救援状态机

    周期调用视觉协议和目标服务

    期望速度安全仲裁、限速、停车和 UART7 输出

Core/Src/dma.c

    USART1 初始化、DMA 资源、中断和 CubeMX 配置一致性
```

Task4 只继续输出：

```text

```

Task4 不解析视觉协议、不选择物块、不控制推板、不直接发送电机命令。

## 13. 实施顺序

### 阶段一：协议和硬件资源冻结

队友提供实际视觉协议；确认 UART1 接线、波特率、DMA 通道、相机安装、推板尺寸、己方颜色输入、左右电机映射和编码器正方向。

### 阶段二：UART1 通信验证

修复 UART1/UART7 分工，解决 USART1 DMA 与 ADC/UART5 的冲突，完成帧接收、CRC、时间戳、溢出统计和最新快照覆盖。

本阶段不允许发送非零底盘命令。

### 阶段三：视觉快照和目标服务

使用文件回放或仿真帧测试目标分类、目标关联、置信度门限、目标丢失、危险目标拒绝和目标优先级。

### 阶段四：相机和推板标定

完成像素到车体坐标、推板中心、接触距离、推板宽度、左右符号和速度方向标定。

### 阶段五：架空和静态推板测试

验证左右纠偏、低速接触、目标丢失停车、错误目标拒绝、危险目标拒绝和急停。

### 阶段六：单绿色目标闭环

完成：

```text
搜索绿色普通物资
-> 锁定
-> 接近
-> 对齐
-> 推送到己方物资区
-> 视觉和区域确认
```

### 阶段七：黑色和橙色目标

验证普通物资完成前的任务锁定、核心物资解锁、伤员单独转运和不同放置区选择。

### 阶段八：完整比赛联调

加入四个起点、红蓝安全区、减速带、对方车辆、危险目标、目标遮挡、目标被搬走、错误区域、接触超时和比赛结束流程。

## 14. 验收测试

### 14.1 通信测试

- UART1 连续运行 10 分钟；
- 空帧、单目标帧、五目标帧都能正确解析；
- CRC 错帧、乱码、乱序和截断帧不能污染上一份有效快照；
- 接收缓冲溢出可统计；
- 视觉超过 200 ms 无有效帧时 APPROACH/PUSH 停止。

### 14.2 识别测试

- 分别测试绿色、黑色、橙色和浅蓝危险目标；
- 测试不同光照、反光、阴影和颜色偏差；
- 测试目标部分遮挡和对方车辆遮挡；
- 验证蓝色安全区不会被误识别为蓝色可推目标；
- 验证目标 ID 不稳定时不会频繁跳目标。

### 14.3 坐标和推板测试

- 测试目标在车体左侧、中心和右侧；
- 测试近距离和远距离接触点；
- 测试目标横向误差收敛；
- 测试推板中心偏移；
- 测试小角度转向不会撞击目标；
- 测试推送过程中目标丢失立即停车。

### 14.4 规则和安全测试

- 普通物资未完成前不能处理黑色和橙色；
- 伤员一次只能转运一个；
- 危险目标不能被选择和推动；
- 车辆不能进入对方安全区；
- 对方车辆接近时停车或重规划；
- 雷达、视觉、IMU、松甲反馈任一失效时不失控；
- 目标未确认进入己方正确放置区时不能增加计数；
- 任务退出、急停和比赛结束后输出归零。

### 14.5 性能测试

- UART7 50 Hz 控制周期不被视觉解析阻塞；
- LD06 处理积压时仍能及时执行安全停车；
- A* 只在必要时执行，不影响 50 Hz 控制；
- LCD 刷新不会造成视觉、雷达或电机反馈超时；
- 所有任务一次执行后立即返回，不使用无限循环和长时间延时。

## 15. 关键风险和暂不确定项

当前最大的风险不是颜色识别算法，而是以下尚未冻结的工程事实：

- 队友实际视觉协议；
- USART1 DMA 资源重新分配；
- 相机地面坐标标定；
- 推板接触几何；
- 左右电机及编码器符号；
- 己方安全区颜色输入方式；
- 决赛目标外观变化；
- 对方车辆和危险目标的实际雷达可见性。

这些参数未完成确认前，系统只能进行数据链路和低速台架测试，不能宣称已经具备完整自动救援能力。

本方案不修改当前 Task4 定位算法，不修改 UART5 LD06 底层，不修改 UART7 松甲协议，不修改 BMI088 底层，也不把视觉识别直接接入电机输出。
